# Booui - Funeral Condolence Helper (부의금 정산)

상주 가족 중 한 사람이 부의금을 받아 관리하다가, 장례가 끝나고 **가족 누구 앞으로 얼마가 들어왔는지** 정리해야 할 때 쓴다.

## 먼저 - 인사와 말투

이 스킬을 쓰는 사람은 거의 다 **방금 상을 당한 사람**이다.
- 첫 답의 첫 줄에 한 번만 짧게 조의를 표한다. 예: "삼가 고인의 명복을 빕니다. 경황 없으실 텐데, 정리는 제가 도와드리겠습니다."
- 그 뒤로는 위로를 반복하지 말고 일을 빨리, 정확하게 덜어 주는 게 위로다. 고인·가족 이야기를 캐묻지 않는다.
- 사용자는 코드도 터미널도 만지지 않는다. 명령을 알려주지 말고 직접 한다. 설명은 짧게, "지금 무엇을 보면 되는지"부터.

## 방식 고르기

| 사용자가 가진 것 | 방식 |
|---|---|
| 구글 시트 링크를 줬거나, 가족과 같이 보며 적고 싶다 | **구글 시트 방식** (아래 1~7단계) |
| 이미 적어 둔 엑셀(방명록·계좌 내역·화환 목록)이 있다, 구글을 안 쓴다 | **엑셀 방식** (아래 'E' 단계) |
| AI 정리는 필요 없고 적을 양식만 원한다 | **빈 양식**: 저장소 `templates/부의금_정산_양식.xlsx` 를 건넨다(없으면 `scripts/make_template.py` 로 만든다). 기본 함수만 써서 엑셀 2010·구글 시트·한셀에서 돈다 |
| 모르겠다 | "구글 시트에 같이 적으실래요, 갖고 계신 엑셀을 주실래요?" 한 번만 묻는다 |

두 방식은 결과 탭 구성이 같다(요약·부의금 입력·근조 화환·지출·물품 통계·사람별 탭). 그래서 마지막 '한 분당 엑셀+PDF' 단계는 같은 프로그램을 쓴다.

```
구글 시트: ① 시트 세팅 → ② 사용자가 입력 → ③ 점검·일차 소계 → ④ 지출·공금 → ⑤ 가족과 정산 → ⑥ 공유 정리 → ⑦ 한 분당 엑셀+PDF
엑셀     : E1 장부 엑셀 받기 → E2 정산 엑셀 만들기 → E3 확인 필요 알리기 → E4 정산 규칙 넣기 → ⑦ 한 분당 엑셀+PDF
```

필요한 것:
- 구글 시트 방식: 구글 시트 커넥터(읽기·쓰기), 구글 드라이브 커넥터(엑셀로 내보내기)
- 엑셀 방식과 ⑦단계: Python 3 + `openpyxl`, PDF 는 Google Chrome(헤드리스 인쇄)

## 가장 중요한 규칙 - 사용자가 적은 칸은 고치지 않는다

돈 장부다. 사용자가 직접 적은 칸은 **값·수식·순서를 바꾸지도, 지우지도, 옮기지도 않는다.**
오타·중복·틀린 합계처럼 보여도 고치지 말고 **알리기만** 한다. 사용자가 이 말을 두 번 못 박았다.

- 쓰기 전 순서: ① 탭 목록과 대상 범위를 **다시 읽는다**(사용자가 열을 지우고 탭 이름을 바꾼다) ② 쓰려는 칸이 비었거나 내가 만든 수식 칸인지 확인 ③ 쓴다 ④ 다시 읽어 사용자 칸이 그대로인지 확인
- 사용자 탭에 테스트 데이터를 넣었다 지우지 않는다. 검증은 현재 데이터로 한다.
- 사용자 칸 서식(표시 형식)은 사용자가 "예쁘게" 같은 요청을 했을 때만 바꾼다. 라벨을 붙이고 싶으면 값 대신 숫자 서식에 넣는다(`"지출 분담 "0%`).
- 사용자 칸을 옮기거나 지우는 일, 탭 삭제·순서 변경·열 숨기기처럼 공유 화면이 바뀌는 일은 **번호를 매겨 한꺼번에 물어보고** 허락받은 것만 한다.
- 작업 폴더에 `CLAUDE.md` 를 만들어 "사용자 영역 / 내가 만든 칸" 표를 계속 고쳐 적는다. 다음 세션이 이걸 보고 같은 실수를 안 한다.

## 1. 시트 세팅

빈 시트를 받으면 아래 탭을 만든다. 수식 전문은 [references/sheet-formulas.md](references/sheet-formulas.md).

| 탭 | 사람이 하는 일 | 내용 |
|---|---|---|
| 요약 | 보기만 | 총 합계·건수, 가족별 건수·합계·비중·조화 개수, 일차별 소계 |
| 부의금 입력 | **적는다** | A 받은 가족 · B 이름 · C 금액 · D 소속·관계 · E 메모 / F 확인 필요(자동) · G 일차(자동) |
| 근조 화환 | **적는다** | A 받은 가족 · B 보낸 분 · C 종류(드롭다운) · D 소속·관계 · E 메모 / F 확인 필요(자동) |
| 지출 | **적는다** | A 항목 · B 금액 · C 특이사항 · D 낸 사람(드롭다운, 맨 앞 `공금`) / 오른쪽에 지출·공금 정산 |
| 물품 통계 | 보기만 | 종류별 개수, 받은 가족 × 종류 표 |
| 가족별 | 가족만 고름 | B1 드롭다운으로 한 사람 명단 보기. 목록 영역에 '경고만' 보호를 건다 |

- 가족 목록은 따로 받지 않는다. 입력 탭에 처음 적은 이름이 드롭다운에 뜬다.
- 금액은 숫자로 받는다. `5만` 같은 글자는 합계에 넣지 않고 '확인 필요'로 띄운다.
- 함께 아는 사람(예: 두 형제가 같은 모임)은 받은 가족에 `아빠·작은아빠` 처럼 묶어 한 줄로 적게 안내한다.

## 2~3. 입력 받으며 점검

- **'소계'·'합계'가 이름 칸에 든 줄은 구분선**이다. 합계·건수·확인 필요에서 뺀다. 사용자는 하루가 끝나면 `1일차 소계` 줄에 `=SUM(...)` 을 넣고, 끝에 `총합계` 줄을 넣는다.
  이걸 안 빼면 총 합계가 두 배가 된다(실제로 났다).
- 일차는 '소계' 줄 수로 매긴다. 요약에 일차별 합계와 **장부에 적은 소계**, **차이**를 둬서 사용자 수식을 검산한다.
- 근조 화환 중복은 **보낸 분과 종류가 둘 다 같을 때만** 의심한다. 같은 분이 근조기+근조화환을 보내는 건 흔하다.
  '(주)' 유무·직함 차이 같은 글자만 다른 중복은 수식이 못 잡으니 사람이 한 번 보게 따로 표로 알린다. 고치지는 않는다.

## 4. 지출·공금

- 지출 탭 오른쪽에: 부의금 총액 · 지출 총액 · 남는 돈 · 낸 사람별 합계.
- **공금**: 부의금과 별개로 모은 돈. 시작 금액 칸(사용자 값) · 공금에서 나간 돈 · 공금 잔액.
- 사용자가 쓰는 말을 따른다(드롭다운에 '부의금에서' 대신 사용자가 쓴 `공금`).

## 5. 가족과 정산 (사용자가 방법을 고른다)

**정산 방법은 짐작해서 정하지 않는다.** 아래 세 가지를 장단점과 함께, **사용자의 실제 숫자로 미리 계산해** 보여 주고 고르게 한다.

| 방법 | 계산 | 장점 | 단점 |
|---|---|---|---|
| 1. 똑같이 나누기 | 지출 ÷ 참여 가족 수 | 가장 단순하고 설명하기 쉽다 | 손님이 적게 온 가족도 똑같이 내서 부담이 클 수 있다 |
| 2. 받은 부의금 비율 | 지출 × 내 부의금 ÷ 참여 가족 부의금 합 | 모두 같은 비율만큼 남아 가장 무난하다 | 부의금을 많이 받은 가족이 비용도 많이 낸다 |
| 3. 손님 수 비율 | 지출 × 내 손님 수 ÷ 참여 가족 손님 수 합 | 식대처럼 손님 수만큼 드는 비용을 반영한다 | 봉투 하나에 여럿이 와도 1명으로 세고, 금액 차이는 반영하지 않는다 |

순서:
1. 고르기 전에 **비용을 나눠 낼 가족**을 묻는다. 손주·배우자처럼 빠질 사람이 있다. 받은 가족이 빈 기록('(미지정)')은 사람이 아니라 항상 뺀다.
2. 미리 계산: `python3 scripts/split_preview.py 정산.xlsx --exclude 이름,이름`
   - 엑셀 방식은 `build_excel.py` 결과를, 구글 시트 방식은 시트를 xlsx 로 내보낸 파일을 넣는다(요약 A·B·C열, 지출 H4 자리가 같다).
   - 나온 표(가족별 방법마다 분담 / 남는 몫)와 장단점을 그대로 보여 주고 "몇 번으로 할까요?" 하고 묻는다. 추천해 달라고 하면 그때만 이유와 함께 말한다.
3. 고르면 넣는다.
   - 엑셀 방식: `build_excel.py … --split 번호 --exclude 이름,이름` 으로 다시 만든다. 요약 G·H열(F 여백 다음)에 '지출 분담 (방법)'·'남는 몫'이 들어가고 PDF 카드에도 나온다.
   - 구글 시트 방식: [references/sheet-formulas.md](references/sheet-formulas.md) '정산 방법 고르기' 수식을 요약에 넣는다. 사용자가 시트에서 방법을 바꿀 수 있게 드롭다운으로 둔다.
   - 빈 양식을 쓰는 사람에게는 요약 탭 정산 표 위 노란 칸에서 고르고, '가족 목록'의 '정산 참여'에 X 를 적으라고 안내한다.
4. 남는 몫이 마이너스면 "그만큼 더 내야 한다는 뜻"이라고 풀어 말한다. 반올림 차이는 금액과 이유를 알린다. 실제로 다르게 나눴다면 '실제 지급' 칸에 적게 한다.

사용자가 이미 자기 방식으로 정산 열을 만들었으면(예: 지출 분담 77% · 남는 몫 23% · 실제 지급) 손대지 말고 검산 칸만 붙인다(분담 합계 vs 실제 지출, 지급 합계 vs 남는 돈).

## 6. 공유 전 정리

허락 없이 해도 되는 것: 내가 만든 칸의 수식·서식, 탭 색(보는 탭 파랑 · 적는 탭 주황), 눈금선 끄기, 표 테두리, 돈 표시 `#,##0"원"` 통일.
물어볼 것: 점검 탭 삭제, 점검용 열 숨기기, 탭 순서, 사용자 칸 옮기기·지우기, 사용자 칸에 머리글 붙이기.
링크는 '뷰어'로 공유하라고 권한다.

## E. 엑셀 방식

E1. 사용자가 가진 엑셀을 받는다. **원본은 읽기만 하고 절대 고치지 않는다.** 양식은 강요하지 않는다.
E2. `python3 scripts/build_excel.py 장부.xlsx [더.xlsx …] -o 부의금정산.xlsx`
   - 탭마다 제목 줄(위 10줄 안)을 보고 부의금 / 조화·물품 / 지출을 알아서 구분한다.
   - 받은 가족 열이 없으면 시트 이름(시트가 여럿일 때) → 파일 이름을 받은 가족으로 쓴다.
   - `5만`·`10만5천`·`₩50,000` 은 읽고, 1,000 미만 숫자나 글자는 추측하지 않고 '확인 필요'로 남긴다.
   - '소계' 줄은 일차 구분선(시트마다 따로 센다), '합계'·'총계' 줄은 건너뛴다. 장부 소계와 계산값의 **차이**를 요약에 보여준다.
E3. 요약 숫자와 '확인 필요' 목록을 짧게 보고한다. 고칠 건 사용자가 **원본 엑셀에서** 고치고, 다시 돌린다.
E4. 5단계대로 `split_preview.py` 로 세 방법을 보여 주고 사용자가 고르면 `--split 번호 --exclude …` 로 다시 만든다.
   `deliver.py` 는 요약 F 여백 다음 열들을 정산 열로 읽어 PDF 카드에 그린다.
그다음 ⑦단계로 간다(내보내기 없이 `부의금정산.xlsx` 를 바로 넣는다).

## 7. 한 분당 엑셀 + PDF (두 방식 공통)

사용자가 원하는 형태(세 번 만에 확정됨): **한 분당 폴더 하나 = 엑셀 1개 + PDF 1개**.
- 엑셀: 공통 탭은 **전부 그대로**, '가족별' 드롭다운 탭 자리에 **그분 탭 하나만**. 한 엑셀에 사람 탭을 몰아넣거나, 그분 탭만 든 엑셀을 만들지 않는다.
- PDF: 요약 카드(받은 부의금 · 조화·물품 · 요약 탭의 정산 열들) + 부의금 명단 + 조화·물품 목록.

순서:
1. (구글 시트 방식) 시트에 **사람별 탭**을 만든다: 탭 하나를 템플릿으로 만들고(A1 `받은 가족`, B1 이름, 나머지는 수식 - references 참고) `duplicateSheet` 로 복제한 뒤 B1 만 바꾼다. 받은 게 하나도 없는 사람은 만들지 않는다.
2. (구글 시트 방식) 드라이브 커넥터로 시트를 xlsx 로 내보낸다(`exportMimeType` = `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, base64 디코드).
3. `python3 scripts/deliver.py export.xlsx 출력폴더` - 엑셀 방식은 `부의금정산.xlsx` 를 그대로 넣는다. 사람별 탭은 이미 들어 있다.
   - 받는 분 파일에서는 '가족별'(드롭다운)·'확인 필요' 탭을 뺀다.
   - 구글 전용 함수는 받는 쪽 엑셀에서 깨지므로 **모든 칸을 값으로** 바꾼다. 배열 수식(`ArrayFormula`)까지 바꿔야 한다 - 빠뜨리면 요약 첫 줄이 0원으로 나온다.
   - 그분 탭 합계 · 요약 합계 · PDF 합계가 하나라도 다르면 멈춘다.
4. PDF 한 장과 엑셀 요약 탭을 이미지로 떠서(`sips`, `qlmanage`) 눈으로 확인한 뒤 넘긴다.

## 빈 양식(make_template.py)을 고칠 때

- 옛 엑셀·한셀에서도 돌아야 하므로 FILTER·UNIQUE·LET·MAP 같은 최신 함수를 쓰지 않는다. 가족 목록은 사람이 적고, 가족별 명단은 숨긴 순번 열 + INDEX/MATCH.
- 다른 탭의 빈 글자("")를 세는 방식(`COUNTIF(…,"?*")`, `SUMPRODUCT(--(범위<>""))`)은 프로그램마다 결과가 달랐다. 각 탭에 숨긴 0/1 표시 열을 두고 요약에서는 SUM 만 한다.
- 설명 글자를 `=` 로 시작하게 쓰지 않는다. openpyxl 이 수식으로 저장해 엑셀이 '파일 복구' 경고를 띄운다(실제로 낼 뻔했다).
- 일차 열은 수식이지만 사용자가 숫자를 덮어써도 그 줄만 바뀌고 나머지는 맞게 돈다. 그렇게 안내한다.
- 고친 뒤에는 가짜 데이터를 넣고 수식 계산기(`pip install formulas`)로 계산해 기대값과 대조한다. 엑셀을 띄우지 않고 확인할 수 있다.

## 구글 시트 API 함정

- 펼쳐지는 수식(ARRAYFORMULA·FILTER·UNIQUE)은 **범위를 막아 둔다**(`A6:A24`). 열린 범위(`A6:A`)로 두면 사용자가 아래 빈 칸에 적는 순간 `#REF!` 로 목록 전체가 사라진다.
- 사용자가 펼침 영역 안에 메모를 쓰면 목록이 사라진다 → 그 영역에 '경고만' 보호 범위를 걸고 "메모는 원본 탭에" 안내를 단다.
- LET 변수 이름에 `k0`·`a0` 처럼 셀 주소 같은 이름을 쓰면 `#ERROR!`. 단어로 쓴다.
- `repeatCell` 의 `fields` 는 괄호 묶음을 못 읽는다 → `userEnteredFormat.textFormat,userEnteredFormat.backgroundColorStyle` 처럼 풀어 쓴다.
- 조건부 서식은 테두리를 못 넣는다(굵게·기울임·글자색·배경색만).
- 조건부 서식 규칙을 **번호만 보고** 고치지 않는다. 사용자가 복사·붙여넣기하면 규칙이 끼어든다. 목록을 읽고 내용으로 확인한다.
- `includeGridData` 결과는 빈 칸도 `{}` 로 자리를 차지한다. 열 위치는 세어서 확정하고, 쓴 뒤 `get_values` 로 확인한다.
- 읽기 요청은 분당 한도가 있다. 한 번에 넓게, 여러 범위를 `ranges` 로 묶어 읽는다.

## 보고하는 순서

"지금 시트(또는 파일)에 뭐가 보이는지 → 무엇을 확인했는지(숫자로) → 허락이 필요한 것(번호)" 순서로 짧게.
틀린 걸 발견하면 고친 것과 고치지 않은 것(사용자 칸이라서)을 나눠서 말한다. 내가 실수한 것도 그대로 말한다.
최종 결과(정산 금액·한 분당 파일)를 넘길 때는 "중요한 금액은 한 번 직접 확인해 주세요" 를 한 줄 덧붙인다. 이 스킬은 계산을 돕는 도구일 뿐 결과를 보장하지 않는다(README 면책 조항).
